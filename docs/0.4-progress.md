# 0.4.0 交接记录

日期 2026-11-25。该版本增加桌面 Git 操作，协作 API 和 MySQL 表沿用 0.3.0。0.4.6 支持携带未提交改动创建分支。0.4.7 增加统一操作确认、Git 与 GitHub 设置，以及任务详情中的代码和验收进展。

在 Windows 安装 Git for Windows 和 Node.js 22.12+，在仓库根目录运行以下命令。

~~~powershell
npm ci
npm run dev
~~~

`npm run pack` 将 Windows x64 免安装版输出到 release/0.4.7。发布时保留整个 TCW-win32-x64 目录。要试账号、项目和任务，另开终端执行 `.\scripts\Start-LocalServer.ps1`，再把客户端服务地址设为 http://127.0.0.1:8080。

1. 打开「本地工作区」，导入本机仓库，或输入 GitHub HTTPS/SSH 地址后选择父目录。克隆成功后自动导入。
2. 在「设置 → Git 与 GitHub」选择该仓库，核对提交姓名、邮箱和各自来源。仓库可以继承全局配置，也可以单独保存或恢复继承。HTTPS 授权由浏览器和 Git Credential Manager 完成。SSH 仓库可检测身份。测试读取权限使用该远程的实际 Git 配置。
3. 登录后，在「协作项目 → 成员与仓库」绑定本机仓库。在「任务」中关联已有分支，或从已确认的当前提交创建任务分支。
4. 回到「本地工作区 → Git 操作」，点击文件名查看差异、勾选文件并提交。在 `main` 或 `master` 上准备开 PR 时，可以先点提交区的「先创建分支」，输入分支名并切换过去，未提交改动会保留。推送前确认当前分支和远程目标。首次推送没有上游时，默认推到 origin 的同名分支。
5. 获取远程状态后可查看领先和落后数。快进更新要求干净工作区和可用上游。分叉时可在「更多」选择「对齐到远程分支」，在确认框按需勾选「保留备份分支」。
6. 任务负责人切换到关联分支后可直接从任务页推送，再提交验收。任务详情显示本机可查的分支进展和项目服务返回的验收进展。提交验收时会提示仓库未提交改动或已知未推送提交。

完整运行说明、代码结构和验证记录位于工作空间的版本文档/0.4。
